## 实现核查与验证范围

实现新增在 `scripts/`，避免改变旧证据生产者对全部 `rl/*.py` 与 `sft_prompt.py` 的源码身份。旧基座特征、情感头和校准器继续保持原生产身份；新运行使用独立身份及输出目录，不修改旧实验或模型。

核查关注以下实际约束：

- 仅白名单内两个用户已确认的基线 hash 可进入导出。CSV 解析、hash 和基线成绩从同一字节快照得到，避免混用新旧基线。
- 新运行应冻结自身基线，并核对该 hash 与运行身份一致，使长时间 GPU 提取前后不能切换白名单内另一个文件。
- 复用头参数须核对完成标记、原训练成员签名、文件 hash、收敛状态和候选内嵌参数；校准器须核对折外训练 ID、概率、签名和完成标记。
- 问题来源是 grounded 源缓存，须核对其 context 自身 fingerprint、预期 source identity、manifest hash 和 manifest identity；不能误用中间 relation context。
- VA 问题输入不带 `text` 或 `text_content`；标签、source_dataset、natural、views 不进入问题回调。sample_id 仅用于索引与审计，实际 prompt 不渲染来源 ID 或监督元数据。
- 只为新增 yes 生成问题。问题字段通过结构验证；现有检查不能单独证明文本中性、面向当前用户，需检查实际 prompt 和生成文本，不能据人工观看测试媒体来修订情感或冲突标签。
- 输出目录使用进程锁，导出字段和 ID 顺序严格核验，禁止删除已有 yes、改变情感、覆盖原 CSV 或覆盖不同候选。
- 单个文件采用排他创建、manifest 最后写。完成状态须成功解析 manifest 并重新核验其记录的所有文件 hash；仅看文件存在不足以判断完整。写入中断可能留下不完整文件，应保留残留原件，在新目录恢复，不能默默覆盖。

本次文档复核使用 `.venv-rl-check` 在工作区临时目录重新运行三个专项测试模块，共 **30 项全部通过**，实际日志为 `runs/evidence-supplement-documentation-tests-20261025.log`。覆盖严格 0.5 边界、argmax 平局、原情感和已有 yes 保留、基线快照竞争、VA 文本过滤、问题断点缓存、来源哈希篡改拒绝、模板终审及不可覆盖导出。测试日志只证明这些 CPU 契约；GPU 推理与 Public 成绩分别由运行产物和实际竞赛页面证明。
