## 数据集真正提供了什么信号

| 数据类别 | 训练 | 验证 |

| 自然数据，VT，Conflict | 107 | 20 |

训练情感标签为 positive 1403、negative 1944、neutral 7；验证为 positive 252、negative 414、neutral 0。自然冲突训练只有 143 条，合成冲突 268 条。原始 v4 六选一在训练自然冲突上正确 110/143（76.92%），在验证自然冲突上仅 4/25（16%）；合成训练冲突正确 263/268（98.13%）。训练样本已被此前的 v4 SFT 使用，这个训练集成绩不能视为独立泛化能力。

这说明需要区分“纠正训练样本”和“对新片段泛化”。它与模型记忆训练分布、合成数据存在可利用的模式等解释相容，但仅凭这些统计还不能证明模型究竟没看懂画面、没听懂音频，还是没有学会比较两种信号。

原始数据中已有 `views.M1`、`views.M2`、`views.M12`：M1 为视觉，M2 为 VT 的文本或 VA 的音频，M12 为综合情感。训练和验证中，Conflict 恰好对应 M1/M2 极性不同，Aligned 恰好对应极性相同。所有综合标签均等于两个模态之一；训练 Conflict 中 263 条综合标签随视觉，148 条随第二模态，不能统一偏向视觉或第二模态。

训练有 30 个同视频的 VT/VA 配对组，两个协议的 Conflict/Aligned 标签不同；验证有 10 个这样的组。它们是输入模态不同产生的合法目标差异，不应合并为同一个不确定性标签。相同视频的视觉标签在两种协议中一致；未发现完全相同可见输入对应不同训练目标。

`use_in_main=false` 的训练样本有 146 条，其中 87 条 Conflict；验证有 31 条，其中 19 条 Conflict。因此不能自动将 false 全删掉，否则会直接删除很多冲突样本。其具体筛选含义需要结合数据说明，不能把该字段直接当作“错误标签”。所有记录的 annotation_count 都是 0，说明该字段没有提供可用的置信度信息，不能据此推断所有标注都不可靠。单模态 is_clear=false 的训练视觉有 20 条、第二模态有 63 条，后续证据奖励应跳过这些不清晰的单模态目标。

## 奖励究竟有没有生效

当前不确定性正确奖励为：Conflict 2.448175、Aligned 0.227931。这两个数字在全训练均匀遍历下，对应 0.3 与 0.2 的总体贡献，算术没有写反。完整奖励表已重建一致，模型参数有更新，55/210 次更新触发梯度裁剪；不能将本轮解释为“完全没有梯度”。

初始六动作最大概率的中位数为 0.999656；2443/3354 条样本的任务目标对六个分数的梯度范数小于 0.001。这些弱梯度大多来自已经正确的简单样本。但漏判的 33 条训练自然冲突的梯度范数中位数为 0.09883，并非普遍归零。它们正确不确定性概率的中位数为 0.02954，有 12 条低于 0.01。全动作枚举确实解决了旧 GRPO 的“正确候选没有采出”问题，却没有自动解决训练信号分配和感知泛化。

需要特别避免三种错误修法：

- 给每条样本的六种动作统一减去一个常数，不改变当前期望奖励目标的策略梯度；将 0/正奖整体改成等价负罚也不会创造新的信息。
- 放大所有奖励只改变其相对 KL 的尺度，不能让模型获得额外视觉或音频证据。
- 追逐格式奖励没有价值：这轮六份验证输出合法率均为 100%。

## 开源代码中可借鉴的设计

下述是实际读取的原作者仓库与论文，不是将数学推理榜成绩视为本任务效果保证。

| 项目 | 已核实的奖励或目标 | 对本项目的意义 |
|---|---|---|
| [R1-Omni](https://github.com/HumanMLLM/R1-Omni/blob/main/src/r1-v/src/open_r1/grpo.py) | 情感答案正确给 1，否则 0；另有格式 0/1 奖励 | 没有通用复杂配方能保证提分；其任务与数据、初始模型都不同 |
| [EasyR1 r1v](https://github.com/hiyouga/EasyR1/blob/main/examples/reward_function/r1v.py) | `(1-format_weight)*accuracy + format_weight*format`，该示例默认 format_weight=0.5 | 格式未学会时有用；本任务不应照搬这个默认比例 |
| [verl DAPO](https://github.com/verl-project/verl-recipe/blob/main/dapo/README.md) | 过滤原始任务指标全相同的采样组，另处理超长惩罚和 token loss 聚合 | 对旧采样式 GRPO 有针对性；当前已经枚举动作，再加同样过滤无法解决泛化 |
| [OPPO](https://github.com/ZhiyuanHan-Aaron/OPPO/blob/main/affect_r1/affect_reward.py) | 情感任务奖励以外，匹配生成的视觉/声音证据与参考线索；结合模态遮蔽及证据 token 的专门损失 | 与 Qwen2.5-Omni 情感任务最接近，关键是奖励可核验的模态证据；我们没有其细粒度线索文本，不能原样照搬 |
| [REBEL](https://github.com/ZhaolinGao/REBEL/blob/main/src/tldr/rebel.py) | 回归一对回答的相对 log 概率变化与奖励差，使用平方损失 | 提供保留 RL 范畴的相对奖励优化方式；它不是奖励函数本身，不能单靠换优化器承诺泛化 |

[OPPO 原论文](https://arxiv.org/html/2606.25325v1)的任务是开放词汇情感理解，证据线索与算力条件也与本比赛不同。本项目只能借鉴“用可核验模态证据训练”和“检查证据来源”的机制，不应照搬其情感轮奖励、权重或声称复现论文收益。[MECap-R1](https://arxiv.org/html/2509.18729v1)用情感锚点的语义相似度结合 BLEU/SPICE；它服务于情感描述文本，不适合替代本项目三个离散情感标签的精确判定。

## 推荐的下一版：保护情感，针对模态冲突做证据约束的 RL

这是根据本轮证据提出的新候选设计，尚未实现或启动，不是已经验证有效的方案。优先改变学习任务与监督信息，不再加一轮固定 F1 增量奖励。

1. **把情感能力保护下来。** 同一 Omni 基座的冻结 v4 reference 负责原来的情感决策与澄清问题；RL policy 只负责不确定性。保持 reference 的输入与解码一致，避免更新共享 LoRA 后破坏已有的情感结果。最终四列 CSV 格式保留。这是对当前 reference/policy 框架的字段分工，不额外引入其他基座。
2. **不再用整段 JSON 前缀的总概率混合六个决策。** 将不确定性变成同一上下文下的 yes/no 条件决策，只评分字段值；固定标点和问题前缀不参与动作评分。先核对 tokenizer 是否为单 token；若不是则严格按规范化值序列计算，不能取第一个 token 冒充完整候选。新规则必须先测零更新基线，确认解码变化的代价。
3. **增加现有标注能核验的证据任务。** VT 分别看静音视觉和文本，VA 分别看静音视觉和音频，使用 M1/M2 的三类标签给正确性奖励。对应模态确实单独输入，避免给模型另一模态然后让它猜目标模态。is_clear=false 的单模态不作为强证据奖励；不伪造 AU、面部动作或声学描述。综合冲突判断仍是模型在完整可见输入上的任务，不把训练标签或真实单模态标签放进测试 prompt。
4. **成对训练纠错和抑制误报。** 用训练集参考预测构建漏判自然冲突与高置信 Aligned 误报集合，配合同协议、同情感/相近来源的普通负例；保留容易样本作为锚点。30 个 VT/VA 不同冲突标签的训练组同时保留并单独诊断。难例只来自训练，不把这轮验证错误或测试数据转成训练对。过采样时明确选择“保持原目标的重要性校正”还是“有意增加难例约束”，不能改了目标却称完全无偏。
5. **使用有界的相对奖励策略改进。** 候选主训练器采用 REBEL 形式，比较同一输入的正确决定与当前最强错误决定；依据在线旧策略的相对 log 概率变化回归奖励差。参考块内冻结，后续块明确刷新；另保留对冻结 v4 的漂移约束。不能把静态旧策略参考一直用到底、设一个有限增量后，就声称一定能翻转原先极强的错误 log odds。

不确定性的主奖励沿用评分权重对应的成本，而不是靠负分换名字：

\[
R_i^U(u)=-c_i\mathbf{1}[u\ne u_i],\qquad
c_i=\begin{cases}0.3/p_C,&i\in C\\0.2/p_A,&i\in A.\end{cases}
\]

这与当前不确定性正确奖励只差一个与动作无关的常数，单独替换不会改善旧目标。真正新增的是可核验的单模态奖励、难负例覆盖、字段隔离与相对奖励的优化路径。单模态辅助奖励采用 \(R_i^{M}=\mathbf{1}[\hat y_i^M=y_i^M]\)，以独立、有限权重的辅助 RL 目标记录，不声称这部分等于 Kaggle 评分。

对同一输入的两个候选，REBEL 形式的基本回归为：

\[
L_{pair}=\left( [\log\pi_\theta(a)-\log\pi_{old}(a)]
-[\log\pi_\theta(b)-\log\pi_{old}(b)]
-\eta[R(a)-R(b)]\right)^2.
\]

在旧策略初始化点，log odds 的误差方向由奖励差提供，不再直接乘以当前较优动作的微小概率。枚举/强制构造本任务候选是对原论文采样方式的任务适配，必须单独验证，不能沿用其理论假设宣称保证提分。辅助权重、参考块长度及总预算应在验收吞吐和信号尺度后固定一次；目前没有实测依据给出一个“必胜”的数值配方。

## 再花长训练时间前的验收

- 用原训练集中按协议/冲突类型分层选出的少量样本验证：单模态任务的正确率、错误决定的相对 log odds 是否按奖励方向移动，以及同批 Aligned 误报是否被压低。这是实现与可学习性检查，不是学习率网格搜索。
- 完整复核零更新 v4 与新字段解码，记录对原始自由生成的差异。先确认输入帧、静音视觉、音轨及文本都按协议送达。若单模态探针显示感知能力不足，先查采样分辨率、音视频对齐和缓存，不盲目提高奖励。
- 输出单模态表现、自然/合成冲突、Aligned 误报、原有情感输出保持情况及逐样本变化。验证集只做阶段选择，不调进训练奖励。
