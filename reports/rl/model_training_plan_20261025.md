## A：先实际训练协议一致的 Omni

先检验已发现的训练问题：历史 VA 实际输入 VTA，且继承 VT/VA 冲突并集；原训练集 411 条 Conflict 变为 441 条。纠正方案保持全部 3,354 条原样本，包括 `use_in_main=false`，VT 输入 V+T、VA 输入 V+A，监督保留原协议标签。

| 对照要素 | control | experiment |
|---|---|---|
| 起点 | 相同 Qwen2.5-Omni-3B 原始基座 | 相同原始基座 |
| 训练数据语义 | 历史 v4 的 VTA/冲突并集 | 原始协议输入与标签 |
| LoRA | rank 16、alpha 32、dropout 0.05 | 相同 |
| 优化 | LR 1e-4、weight decay 0.01、batch 1、累计 16 | 相同 |
| 损失 | emotion 0.5、uncertainty 0.4、其余 0.1；Conflict 权重 2 | 相同 |
| 采样与预算 | Conflict 2x、视频 2fps、最多 64 帧、每帧 50,176 像素 | 相同 |
| 训练上限 | 3 epoch | 相同 |

两组统一使用 SDPA，记录与历史 v4 FA2 的运行差异，不宣称精确复现历史环境。保持原 v4 配置文件不变。独立 SFT 环境避免更改现有 RL 环境。

只使用原始训练集进行按视频与媒体 SHA 合并的 60%/20%/20% 分组，同视频 VT/VA、重复内容不能跨组。固定 split seed 42；两组用相同划分。每个 epoch 在开发集生成完整输出，以综合 Score 选 checkpoint，然后只评估选定 checkpoint 的留出集结果。开发/留出均使用原始标签及正式协议输入，不读取官方 val/test 选模。

seed 42 对照完成后，综合分提高至少 0.01、情感 Macro-F1 下降不超过 0.005、自然冲突识别不下降，才进入 seed 43 复验。两个训练 seed 均通过，才按开发阶段确定的轮数在全部原始训练数据上训练最终模型。不能从训练 loss 下降推断 Kaggle 提分。

执行入口：`python -m scripts.protocol_sft_ablation prepare` 与 `train --arm control|experiment --gpu 1`。实际划分、样本数、配置、checkpoint 及评估结果由独立运行目录保存。

## B：更换视觉表示，再决定是否训练更大的专家

引入 **Qwen3-VL-8B-Instruct** 的视觉专家，保留现有 Omni 文本、音频分支。它提供新的视觉表示；模型参数更多本身不能证明本任务更好。

第一步在 GPU 2 对 32 条训练视频做实际预检，覆盖最长训练视频，确认显存、速度、视频预算与音频隔离；之后提取全部 2,104 个训练视频的冻结视觉特征。与旧视觉分支使用相同内容分组、监督、情感头及校准流程，第二模态输出保持相同。主三折任务分量提高至少 0.01、自然冲突识别不下降、父目录压力测试不下降，才晋级。此时评估的是证据分支，不能冒充完整融合系统的独立评估。

若新视觉证据有用，再训练视觉 QLoRA：只对清晰的 M1 视觉标签做单模态情感监督，不能用融合情感标签冒充视觉标签；不清晰模态仍保留在主任务样本中。融合层在原始协议的 M12 情感与 Conflict 标签上训练，分开学习情感及不确定性。具体训练配置在该阶段开始前冻结，不因 Public 反馈反复改阈值。

新旧模型具有不同的采样取整、patch 与预处理，虽然对齐帧率、帧数及每帧预算，也不能声称逐帧逐像素完全一致。

## 每轮交付与停止条件

每轮报告综合分、情感 Macro-F1、自然/合成冲突识别、VT/VA 分层、普通误报、新增正确和错误。缺失 neutral 的本地计分保留固定三类与另一诊断口径；绝对本地分不直接对比 Public。

未通过开发门槛的模型不生成测试候选。晋级后冻结模型与配置，再生成一次完整候选、检查提交接口与变化清单。新的具体候选准备好后再执行对应的提交批准流程，不连续提交未经验证的变体。
